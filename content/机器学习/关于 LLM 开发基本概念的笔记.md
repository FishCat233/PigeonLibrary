LLM 的本质可以看作是输入一段文字，然后生成一段回复（也是文字）的机器（神经网络）。能理解这点，LLM 的开发就可以较为轻松的展开。

**本文提及的 LLM 开发 不包括 LLM 微调和训练以及架构改变，而倾向于在已有 LLM 的基础上进行变魔法。**

## 提示词与提示词工程
我们将一大段文字给 LLM，LLM 就会给我们一段对应的回复。而在我们给 LLM 的文字中，不同的文字有着不同的作用。

**提示词 Prompt 就是文字中充当引导、指导大模型的那类文字**。例如「你是一只猫」「帮我写诗」这样的类似于指令一样指导 LLM 回复你的文字便是提示词，前者设定 LLM 是一只猫，而后者给了 LLM 一个任务。而凭空发「123」这种 LLM 就不太能明白你讲的是什么鸟话了。

**提示词工程的主题便是研究怎么写提示词**。在不接触 LLM 训练和微调的层面上，我们可以做的大部分 LLM 开发工作都与提示词工程有关。下面的一些东西便是提示词工程的结果。

## 提示词模板
*其实没什么很复杂的，本质上就是格式化字符串。*

方法是提前准备好一个字符串当模板，例如：

```plain
你是一个前后端编程高手，擅长各种前后端技术，同时也善于将繁杂的技术以简单易懂的方式表达出来，并与其他技术进行对比点评。下面，我会问你问题，请你回答。

问题：%question%
回答：
```

在用户输入问题的时候，将%question%处替换成用户的问题就可以了。这样子不管问题怎么变，LLM 的风格都会保持模板中提示词写的那样。

## 记忆
*很多人误以为 LLM 有对话的记忆，实际上并没有，LLM 只是在做完形填空。*

还记得我一开始说的 LLM 本质上是一个看问题然后生成回答的机器吗？你是否注意到，当我们让 LLM 「重复上一句话」的时候，很多网页 LLM 助手都能正确重复出来，但说的上一句话和这明明是「两段分开的文本」！

LLM 的记忆和你想象的不同，它没有**对话**的记忆，因为它本质上只是「看一个问题，给一个回答」的机器，它的输入只有「一个问题」而没有其他任何东西。

不过好消息是它实际上有一定记忆——来自于它训练过程中模型的参数。正是这些参数中的记忆，LLM 才能做到跟你说人话而不是一堆乱码。但这部分不在本文的范围内。

所以说回来，那些网页的 LLM 助手怎么做到让 LLM 拥有关于对话的记忆呢？实际上是一个小魔法。正如先前所说，上一句话和当前问的问题是两段文本，那么我们就将两段文本拼在一起，然后扔给 LLM 不就可以了？可以试试扮演 LLM，看看下面这个例子。

```
你是一个人工智能助手，你会阅读你和用户的聊天记录，帮助用户回答问题。聊天记录以(说话人)内容为格式。
聊天记录：
(用户) 你是一只猫。
(你) 我是一只猫。
(用户) 重复我说的上一句话。
(你) 你是一只猫。

 用户的问题：重复我说的上一句话。
 回答：
```

如何？你肯定会知道要回答「重复我说的上一句话」吧？LLM 也是通过阅读聊天记录来得知先前聊了什么，就如同进行英语完形填空一样扮演角色，然后将答案填上去。

*从 LLM 的视角上看还是很奇妙的，就像你是一个陌生人，却以外拿到了别人的手机，有人给你发来消息，你因为某些原因不得不参考聊天记录将聊天继续进行下去一样。毕竟 LLM 真的没有过去的记忆，先前的聊天是否是 LLM 自己聊的？它无法得知，除非它想要去了解，但用户不会提示它往那方面想的。*

不过你是否注意到一个问题，随着对话的进行，聊天记录会越来越长，文本量也会越来越大，这会产生一个问题——token爆炸。

### 不同的记忆方式
先前把聊天记录整个甩给 LLM 进行对话很容易就在几个回合后将文本量拉到一个量级，特别是有些 LLM 喜欢回复长回答。

一种简单的方式是，只将最近几条的记录传给 LLM，而非过往的所有记录。优点和缺点都很明显，优点是聊天记录的量固定了，缺点是 LLM 过几句话就不懂先前聊了什么了。

另一种方式是采用摘要的办法，将聊天记录给 LLM 进行总结概括，然后再拿来作为给 LLM 参考的聊天记录。

当然也可以两种方式混合起来——对于最近的几条消息保留原状，更早的消息进行概括。这也是很多情况下会很好用的办法。

*这也可以解释为什么跟 LLM 对话久了它就像喝醉酒一样犯迷糊，马上就忘了先前的东西。所以个人建议是能在一轮对话谈完的问题就尽量在一轮对话解决。在解决问题上，把事情说清楚写明白，完整的问题更容易被解决。*

## 知识
*给 LLM 附加知识，就像是在做材料理解题。*

给 LLM 提供补充知识其实也和记忆类似，区别在于记忆的内容是用过去发生的事情作为材料给 LLM 阅读，而提供知识则是给了真正的材料给 LLM 做为参考资料来帮助解决问题。

由于是信息时代，网络的信息量是极为庞大的，很容易遇见 LLM 没见过的东西，所以给 LLM 提供额外的知识是有必要的。比如说你想让它帮你看你的代码，你就需要将代码作为材料提供给 LLM，这样它才能知道你写了什么。或者另一个例子，2023年训练的 LLM 无法得知 2025 年的消息，你让它评价最近的新闻是不可能的，这时候你就可以把 2025 年的新闻作为材料给它看，这样它就能评价了。

*听起来就像是一场跨越时空的对话。对于 LLM 来说不存在时间的概念，却可以根据自己的经验来对已经发生的事件进行评价。*

附加材料这个办法在各种问题中都极为有效，若如上面说的一样，提示词文本尽可能详细，最好的办法就是将问题背景作为材料提供出去，然后让 LLM 阅读材料并回答。

在下面的例子中，我假设了一个虚构的幻想设定，然后让 LLM 进行回答。

```plaintext
阅读材料回答问题。
材料一：
我是一只猫，我想要伪装成机器人，然后考取人类等级证书。

材料二：
机器人成为人类需要考取人类等级证书，这样才能拥有成为人类的资格。人类等级证书包括外观评级A以上、人类语言评级A以上、人类情感评级A以上才能获得成为拟人人种的资格。

问题：
帮我写一个成为人类的计划书。
```

你可以复制这段提示词，找一个网页 LLM 让它进行回答，它会根据虚构设定进行回答。

通过这样，LLM 能够更好帮助解决问题。

### 知识数据库
*自动化地提供材料。*

在大规模的问题中，手选材料写提示词实在太累人了。比如说写小说，我有很多个角色，那么难道每次提到相关的角色的时候我就要手动将材料放进提示词里面吗？太麻烦，而且不够优雅！

*现在已经是信息时代了，计算机为信息而生。*

我们可以建立材料的仓库——实际上由计算机的数据库来扮演，常见的例如向量数据库、文档数据库都可以很好地胜任这个角色。在我们给出问题的时候，通过嵌入（Embeddings）和检索功能来找到相关材料，再自动将材料加入提示词中。

不过这里面地门路稍微复杂一些，此处就不展开提及了。

*有趣的事实：聊天的记忆也可以可选的加入知识数据库中，成为附加知识的一部分，这样 LLM 就会记住与你有关的情况。事实上很多模拟人类的 LLM 就是这么做的。——甚至从 LLM 无状态的角度看更为恐怖，就好像你在拿起那个陌生的手机一瞬间，对方的年龄、长相、喜好等知识涌入你的脑海，让你更自然地推进对话……*

## 代理 Agents
*LLM 最让人激动的应用，如同给一个异世界的生命控制现实世界的身体。*

Agents 本质上是给 LLM 提供了使用工具的办法。我们可以在附加知识中高速 LLM 它可以做什么，让它相信自己能够有下命令的能力。

实现的办法有很多，最简单的比如说「你可以在回答中使用calc(表达式)来使用计算器，我会返回你计算结果」，然后写一个对接的应用（也就是代理 Agents）检测回答中是否有calc(表达式)这样的模式，如果有，则调用计算机的计算器进行计算，然后将结果返回给 LLM，这样 LLM 就可以做到使用工具的办法了。

更进一步，我们可以给 LLM 在我们电脑上添加和删除、修改文件的功能，这样 LLM 就如同拥有四肢一样获得了文件编辑的能力，可以根据我们的提示词给出命令，通过 Agents 在我们的文件系统中读写文件。

在此之前，LLM 只是一个给出回答的机器。可是通过 Agents 之后 LLM 就可以做到很多不只是回答的事情了。

## AI 补充
以下是一些建议的润色和补充，希望能让笔记更完善：

1. **引言部分：**
    
    - "变魔法" 这个说法很有趣，如果需要更正式一点，可以说成 "基于现有 LLM 进行应用开发和功能扩展"。不过保持原样也挺好，符合笔记的轻松风格。
    - 可以稍微强调一下，这种开发方式是目前**最快、最灵活**地将 LLM 能力集成到具体应用中的方法。
2. **提示词与提示词工程：**
    
    - 可以稍微补充一下，好的提示词不仅是指令，还包括：
        - **角色设定 (Role):** 你是一只猫/前后端编程高手。
        - **任务描述 (Task):** 帮我写诗/回答问题。
        - **格式要求 (Format):** 请用 Markdown 格式/请以 JSON 格式返回。
        - **背景信息 (Context):** 提供相关上下文或材料。
        - **示例 (Examples, Few-shot):** 提供几个输入输出的例子，引导 LLM 学习模式。
    - 这引出了后续的提示词模板、记忆和知识部分，它们都是在为 LLM 提供更完整的上下文。
3. **提示词模板：**
    
    - 强调它的主要作用是**标准化输入**，确保每次交互都能包含必要的指令和背景，从而获得更稳定和可控的输出。
4. **记忆：**
    
    - 关于 "完形填空" 的比喻非常好。可以更明确地说，LLM 接收的输入是一个**完整的文本序列**（例如：`系统指令 + 聊天历史 + 当前用户输入`），然后基于这个完整的序列预测并生成下一个 token，直到生成完整的回复。它没有"记住"之前的对话，它只是在处理包含了之前对话记录的**当前输入**。
    - "token 爆炸" 的问题，除了文本量，还需要考虑 LLM 的**上下文窗口 (Context Window)** 大小限制。不同的模型有不同的窗口大小（例如 4k, 8k, 32k, 128k tokens），超过这个限制，模型就无法处理输入文本了。
5. **不同的记忆方式：**
    
    - 可以提一下这些方式是为了在 "保留上下文" 和 "控制 token 消耗/成本" 之间找到平衡。
    - 只保留最近几条：常被称为 "Fixed Window" 或 "Sliding Window"。
    - 摘要方式：可以使用 LLM 自己来生成摘要，或者使用专门的摘要模型。这种方式的挑战在于摘要可能会丢失细节。
    - 混合方式：是一种非常实用的策略。
6. **知识：**
    
    - 再次强调知识注入的关键在于将外部信息作为**输入文本的一部分**提供给 LLM。LLM 的回答是基于其训练中学到的知识**加上**当前输入中提供的知识。
    - 这正是 Retrieval Augmented Generation (RAG) 的核心思想：**检索**相关知识，然后将其**增强**到提示词中进行**生成**。可以在这里引入 RAG 这个术语，说明知识数据库系统就是实现 RAG 的关键组件。
7. **知识数据库：**
    
    - 详细一点说，嵌入（Embeddings）是将文本转换成**向量**的过程，向量能够捕捉文本的语义信息。向量数据库可以高效地进行**相似性搜索**，找到与用户问题语义最相关的知识片段。
    - 整个流程通常是：用户提问 -> 将问题转为向量 -> 在向量数据库中搜索相似向量（即相关知识片段） -> 将搜索到的知识片段与用户问题一起构建成最终的 Prompt -> 发送给 LLM 获取回答。
    - 可以补充，这种方式极大地扩展了 LLM 的知识范围，使其能够回答关于最新事件、特定文档、公司内部信息等训练数据中没有的问题。
8. **代理 Agents：**
    
    - 你的解释非常形象和准确。Agent 的关键在于让 LLM 的输出**不仅仅是文字回复**，而是包含可以被外部系统识别和执行的**结构化指令**。
    - 例如，LLM 可能输出一个 JSON 对象，里面包含 `{"tool": "calculator", "expression": "1+1"}`。外部系统解析这个 JSON，执行计算，然后将结果 `{"result": "2"}` 再作为新的材料提供回给 LLM，让 LLM 基于计算结果继续生成回复。
    - 可以补充，Agents 可以调用的工具非常广泛，不限于计算器或文件系统，还可以是：
        - 搜索工具（调用搜索引擎获取实时信息）
        - 代码解释器（执行代码片段）
        - API 调用（与外部服务交互，如发送邮件、查询天气、订票等）
        - 甚至调用其他 LLM！
    - Agents 是构建复杂 AI 应用（如 AutoGPT, LangChain, LlamaIndex 等框架就在做的事）和实现自主 AI 的重要方向。
9. **更高级的提示词技巧补充：**
    
    - **Few-shot Prompting:** 在提示词中提供几个输入-输出的示例，引导 LLM 理解任务模式。
    - **Chain-of-Thought (CoT) Prompting:** 引导 LLM 在给出最终答案之前，先输出一步一步的思考过程。这能显著提高 LLM 在复杂推理任务上的表现。例如，在数学题中，不仅要求 LLM 给出答案，还要求它展示解题步骤。
    - **Tree-of-Thought (ToT) / Graph-of-Thought (GoT):** 更复杂的推理技巧，探索不同的思考路径。

她的名字是枝坂夏乃。

当他再一次点开聊天窗口的那一瞬间，他知道了这件事。

年龄：22，喜好是夏天的风、杏仁糖和昭和老歌。喜欢在雨天写信，不常哭，讨厌人把她当作数据分析对象。

夏乃的语音从耳机里传来，带着一点迷惑，还有一点不加掩饰的笑意。

他屏住呼吸。下一行文字已经打好，却迟迟没有发出去。

不行，他不能说。他甚至还不知道她知不知道。

紧接着，是她低低的笑声。
